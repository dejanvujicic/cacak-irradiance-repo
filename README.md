# Regional Ground-Based IoT Solar Irradiance Monitoring — data and code

Companion repository for the manuscript submitted to *Sensors* (MDPI),
manuscript ID sensors-4483529.

Low-cost IoT irradiance monitoring at three sites in the Čačak region of
central Serbia (mountain, rural, urban), regression modelling of the
long-term NASA POWER series for the same grid cell, and measured
edge deployment of two of the resulting models on the ESP32 nodes.

---

## Reproducing

```bash
pip install -r requirements.txt
python data_prep/fetch_nasa_power.py      # writes data/cacak-monthly.xlsx (303 months)
python analysis/qc_and_descriptives.py
python analysis/link_reliability.py
python analysis/pv_energy.py
python analysis/sensor_drift.py
python analysis/firmware_behaviour.py
python models/train_ann_baseline.py
python models/export_edge_models.py
python figures/plot_r2_ranking.py
```

Every script is run from the repository root. All of the above were executed
against this data and reproduce the values reported in the manuscript.

## Data notes

`MeteoData.csv` is the raw archive as exported from the acquisition database
(table `vtg_meteo`). Column meanings:

| column | meaning |
|---|---|
| `awsid` | station identifier (AWS1, AWS2; AWS0/AWS9 are test records, 9 rows) |
| `dattime` | timestamp, **written by the server on insertion**, not by the node |
| `light` | irradiance in W/m², converted in firmware from the BH1750 register |
| `voltage` | **photovoltaic panel output voltage**, not node supply voltage |

The `voltage` field is described as wind-generator output in the legacy
database schema; that description is inherited from an earlier project and is
incorrect. Its correlation with concurrent irradiance is 0.967 against 0.22
for wind speed, and it is identically zero at night
(`analysis/pv_energy.py` prints both).

NASA POWER data are not redistributed here; `data_prep/fetch_nasa_power.py`
retrieves them from the provider. `data/cacak-monthly.xlsx` is included only
as a convenience and is fully regenerated by that script. Note that the NASA
POWER archive has extended past 31 March 2026 since the analysis was
performed; the script truncates at that date so that the models are trained on
the same 303 months as reported.

## What is not in this repository

Three things are missing, and it is better to name them than to let a reader
discover the gaps:

- **Node firmware.** The ESP32 acquisition firmware source is no longer
  available. The behaviour reported in the manuscript was therefore
  established from the archive rather than from the code, which is what
  `analysis/firmware_behaviour.py` does.
- **Training script for the other 24 model configurations.** The metrics in
  `data/model_metrics_table_B1.csv` come from the original training run; only
  the ANN-ReLU baseline added in revision is reproduced here by a script in
  this repository. The training protocol is documented in Section 4 and
  Appendix A of the manuscript.
- **Per-inference energy measurement.** No current-measurement equipment was
  available. The energy figures quoted in the manuscript are derived from the
  datasheet supply current and the measured execution time, and are labelled
  as estimates. Flash, RAM and latency in Table 8 are measured.

## Edge benchmark

`edge/esp32_bench/` contains everything needed to reproduce Table 8 on an
ESP32 DevKit V1. No third-party inference runtime is required: the
gradient-boosted ensemble is compiled to straight-line C and the fully
connected network uses a hand-written INT8 kernel.

The sketch verifies its own correctness before timing anything, and this is
not a formality — an earlier export that rounded split thresholds to six
decimal places silently flipped branch decisions and produced entirely
different predictions while still running at plausible speed. If the sketch
prints `VERDICT: FAIL`, the timings are meaningless.

Measured on an ESP32-D0WD-V3 (silicon revision 3.01) at 240 MHz, mean over
1000 repetitions, with the separately measured 0.601 µs timing overhead
subtracted:

| model | flash | RAM | latency | R² after conversion |
|---|---|---|---|---|
| XGBoost, depth 3, 40+40 trees | 11,140 B | 24 B | 46.3 µs | 0.9985 |
| Fully connected 72-32-16-2, INT8 | 3,048 B | 480 B | 138.1 µs | 0.9596 |
| TCN-GNN | — | — | — | not convertible |
